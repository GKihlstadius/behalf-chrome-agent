The problem

Every tool that can click starts a browser that knows nothing about you.

Screenshots and DOM dumps let an agent read the web. Clicking is the easy part. The hard part is that automation frameworks spawn a clean browser: no cookies, no sessions, no BankID, no logged-in state.

So the agent can browse the public web, and nothing else. The moment the work actually matters, whether that is your accounting system, your bank or a government portal, it is locked out at the login screen.

behalf attaches to the browser you already use. Separate profile, your real logins, one port you open and close yourself.

19 commands

open, read, wait, click, fill, upload, shot, pdf, eval. One line each. No SDK, no boilerplate.

Any agent

It is a CLI. Claude Code, Codex, Cursor, Zed, a local model, anything that can run a shell command.

Zero install

Uses the Chrome you have and Node's built-in WebSocket. No 300 MB browser download, no dependencies.

What it looks like

The whole API is a command line.

# start the controlled browser, auto-closes after 90 min
$ behalf start 90

Trust

This tool can act as you. Read it before you run it.

behalf can file your tax return, move money in your accounting system and act in your name on a government portal. That is the point, and it is also the risk.

So it is built to be inspected. The entire tool is 669 lines of plain JavaScript. No dependencies, no build step, no minification, no telemetry, no network calls except to the browser on your own machine.

It ships with its own test suite: 51 checks that drive a real Chrome against a local fixture, plus unit tests for the parts that differ per operating system. Run them before you trust it.

  • Random port, bound to 127.0.0.1, never reachable from the network
  • Separate Chrome profile, your everyday browser is untouched
  • behalf stop closes the port. Nothing runs in the background
  • Auto-shutdown timer so a forgotten session cannot stay open overnight

CDP has no authentication. Any process running as you can reach an open port. behalf makes the window small and explicit rather than pretending the problem does not exist.
